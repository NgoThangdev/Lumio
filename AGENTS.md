# Lumio repository guidance

- **Source hierarchy:** [master prompt](docs/specs/master-prompt.md) is authoritative for product behavior. [Phase 1 scope](docs/specs/phase-1-scope.md) narrows scope. [Technical design](docs/specs/technical-design.md) records early architectural decisions, not current implementation status. Read the relevant slice and API contract for the task; verify current behavior in source, migrations, and tests. Historical implementation notes are not evidence that a feature is still missing.
- **Repository:** npm workspaces `apps/api` (NestJS, Prisma/PostgreSQL), `apps/web` (React/Vite), and `packages/shared`. Root `package.json` has no run scripts. From the root: `npm run start:dev -w @lumio/api`, `npm run dev -w @lumio/web`, `npm run build -w @lumio/api`, `npm run test -w @lumio/api`, `npm run test:e2e -w @lumio/api`, `npm run lint -w @lumio/api`, and `npm run build -w @lumio/web`. API formatting check: run `npx prettier --check "src/**/*.ts" "test/**/*.ts"` from `apps/api`. Prisma commands run from `apps/api`; verify the target and migration status before database changes. E2e tests use the configured local database. See [deployment context](docs/deployment.md); do not infer the live platform from old trial config files.
- **Shared worktree:** FE and BE agents may read the entire repository, including contracts. Edit another app only when the task explicitly scopes that edit. Preserve all existing staged, unstaged, and concurrent user changes; inspect status before work, avoid broad formatting or cleanup, and do not commit unless asked. Hand off changed paths, contract effects, migrations, checks actually run, and integration still unverified.
- **Task brief:** Frame work with **Goal / Context / Constraints / Definition of Done**. Resolve decisions against the source hierarchy and report any product ambiguity rather than silently adding requirements.
